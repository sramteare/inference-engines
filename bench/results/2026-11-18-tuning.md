# Tuning run, 2026-11-17/18

Machine:
- GPU: RTX PRO 6000 Blackwell Max-Q 96 GB. It also drives the desktop (~3.4 GB).
- CPU: Threadripper PRO 9955WX, 16 cores.
- RAM: 122 GB. Disk: Samsung 9100 PRO.
- llama.cpp v1.0.0 (b1b770d90).

Rule for every change: no loss of model quality. That means no lower quants, no expert skipping, no biased routing and
no lossy drafting.

Speed numbers come from `bin/llm-bench --max-tokens 512` on 127.0.0.1:8010 unless noted:
- "Gen" is the warm median.
- "After long" is generation right after the long prompts.
- Raw JSON for the runs is in `2026-11-18/`.

**Outcome:** `llm-serve qwen` (the default) now starts **Basalt**, and `llm-serve deepseek` starts **Maya**. The tuned
llama.cpp profiles stay available as `qwen-llama` and `deepseek-llama`.

## Quality: KL divergence (lower is closer)

The test set is wikitext-2 in 512-token chunks, scored on positions 256-510:
- The BF16 references are the published `jesdga/basalt-kld-bases`, sha256 verified, made with `llama-perplexity`.
- Other engines are scored with `bench/kld_compare.py`, which mirrors llama.cpp's KL code.
- Both models' GGUFs have `add_bos = false`, so every engine gets the raw first token, the same as the references.

| Against the original BF16 model (same quant file) | Chunks | PPL (BF16) | Mean KLD | Same top-1 |
|---|---|---|---|---|
| Qwen, llama.cpp | 100 | 3.3249 (3.2733) | 0.0576 | 92.23% |
| Qwen, Basalt | 100 | 3.3308 (3.2733) | **0.0494** | **92.83%** |
| DeepSeek, llama.cpp | 100 | 2.7298 (2.7314) | 0.1503 | 88.48% |
| DeepSeek, llama.cpp | first 20 | 2.2672 (2.2717) | 0.1375 | 91.08% |
| DeepSeek, Maya | first 20 | 2.2915 (2.2717) | 0.1366 | 91.00% |

Noise floor:
- llama.cpp against itself at another batch size: KLD 0.018 on Qwen and 0.020 on DeepSeek.
- Basalt against llama.cpp on Qwen: KLD 0.031.

### DeepSeek against its reference computation

The reference is Maya's `tools/ds4/ref_gguf.py`, run on the same UD-Q2_K_XL weights:
- **What it is:** a PyTorch forward that follows DeepSeek's `inference/model.py`. It shares no code with Maya's engine.
- **Local patch:** on the Maya branch `local/ref-gguf-kquants`, it reads a Q5_K Engram table and runs the experts on 16
  CPU workers (relative difference 4.2e-7 against the serial path).
- **Input:** one chunk at 128 tokens and one at 512, with identical tokens for every engine.

| Same Q2 weights vs the reference | 128 tok: KL / top-1 | 512 tok: KL / top-1 |
|---|---|---|
| Maya | **0.003 / 100%** | **0.018 / 97.3%** |
| llama.cpp (default, TF32 on) | 0.042 / 98.4% | 0.049 / 95.7% |
| llama.cpp, `NVIDIA_TF32_OVERRIDE=0` | 0.020 / 98.4% | 0.025 / 98.0% |

What this shows:
- **Both engines compute the model correctly.** A side-by-side review of llama.cpp's `deepseek41` code against the
  reference found no difference in formula, constant or order of operations.
- **What was checked:** hyper-connections, norms, attention, RoPE/YaRN, compressed attention, Engram, MoE and the head.
  llama.cpp's Engram hash inputs match DeepSeek's method exactly, and its sparse-attention path is identical to dense.
- **What's left is numeric precision.** About half of llama.cpp's remaining gap is TF32 in its CUDA FP32 matmuls (the
  hyper-connection mixes and the router). Maya is slightly closer to the reference. Against BF16 both engines are equal,
  because the 2-bit quantization dominates.
- **Pitfall:** never give one engine BOS and another the raw first token. An earlier comparison here did, and it made
  llama.cpp look broken (KL 0.15-0.24) and Maya look "better than BF16". Both results were wrong and are withdrawn.

## Ruled out or blocked

- **Our share-max-batch patch** (`--moe-cache-cpu-share-max-batch`): correct, but no gain.
- **Port of #26414** (`--pin-hot-experts`): has bugs (a non-contiguous copy, double counting, the mlock limit).
- **Port of #30970** (`--slot-attach`): unsafe on `deepseek41`, because only `deepseek4` is excluded.
- **Port of #30594** (hybrid cache): aborts when there are zero experts.
- **#32076:** no gain.
- **Xolotl:** its speed comes from biased routing, which is lossy.
