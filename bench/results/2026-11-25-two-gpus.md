# Two GPUs: what each model gets from the second card (2026-11-25)

The machine now has two RTX PRO 6000 Blackwell Max-Q cards (96 GB, 300 W, PCIe 5.0 x16). GPU 1 also drives the
desktop, about 2.7 GB. Until now every llm-serve profile pinned GPU 0. This note measures one card against two for
both Basalt 0.5.6 builds in `~/dev/basalt-builds`, and is the basis for the new defaults:

- **DeepSeek** runs on both cards (`GPUS=0,1`, the new default).
- **Qwen** stays on one card. `qwen-pair` runs one Qwen server per card, and `duo` runs Qwen on GPU 0 and DeepSeek on
  GPU 1.

## Speed

`basalt-bench --gpu <cards> --seed 1 -t conv,struct,prose -p 16384 -- <flags>`, with
`CUDA_DEVICE_ORDER=PCI_BUS_ID`:

- Qwen flags: `--kv fp16 --max-context 262144 --vram-reserve-mib 3772 --resident-experts --vision`.
- DeepSeek flags: `--max-context 524288 --vram-reserve-mib 3772 --vision`.

**basalt-bench needs `--gpu 0,1`.** Without it, it runs on GPU 0 alone even with both cards visible, and only warns
that GPU 1 is unused.

Tokens per second: prompt read of 16k tokens, then generation by task.

| Run | Prompt (16k) | conv | struct | prose |
|---|---:|---:|---:|---:|
| Qwen, one card | 7190–7290 | 285–286 | 473–481 | 236–240 |
| Qwen, `--gpu 0,1` | 7267 | 288 | 476 | 238 |
| Qwen pair, card 0 (both busy) | 7223 | 266 | 469 | 238 |
| Qwen pair, card 1 (both busy) | 7571 | 269 | 490 | 251 |
| DeepSeek, one card | 2327–2330 | 99–114 | 198–200 | 91–96 |
| DeepSeek, `--gpu 0,1` | 2569–2578 | 121–130 | 249–251 | 108–110 |

- **Qwen gains nothing from a second card.** All its experts already fit on one, so a split only adds a hop. Two
  single-card servers running at once each keep almost full speed, so the pair has about twice the total throughput.
- **DeepSeek gains 10% on prompts and about 15–25% on generation.** The second card holds experts that would otherwise
  be read from system RAM.
- DeepSeek on one card was about 15% below the 2026-11-23 numbers on the same build. The machine was not fully quiet
  during part of this run (load around 11 at one point). That is not explained yet, and it affects both rows alike.

## Terminal-bench sample

harbor 0.26.0, `terminal-bench@2.0`, agent `terminus-2`, model `deepseek-v4.1-flash` through llm-serve, one attempt per
task, `--agent-timeout-multiplier 2`. Six tasks that the 2026-11-20 quiet Basalt baseline solved
(see `2026-11-19/terminal-bench/results.csv`).

| Task | One card | Two cards |
|---|---|---|
| break-filter-js-from-html | pass, 3.8 min | pass, 4.6 min |
| git-multibranch | pass, 7.3 | pass, 9.5 |
| headless-terminal | pass, 5.2 | pass, 6.3 |
| largest-eigenval | pass, 3.5 | fail, 4.8 |
| llm-inference-batching-scheduler | pass, 10.9 | pass, 11.9 |
| tune-mjcf | pass, 9.0 | pass, 11.2 |
| **Total** | **6/6, about 40 min** | **5/6, about 48 min** |

- **The two-card failure is a timing check, not a wrong answer.** 26 of 27 checks passed, including every eigenvalue.
  `test_speedup[5]` failed, which times one small matrix in microseconds.
- **Two cards took longer here because the agent wrote more:** about 178k output tokens against 164k (tune-mjcf took 20
  steps instead of 13). One attempt per task can't show a speed difference; the table above is the better guide.

## Two models at once

`llm-serve -d duo`: Qwen on GPU 0 at :8000, DeepSeek on GPU 1 at :8001.

- **Memory:** Qwen holds 81 GB on GPU 0. DeepSeek holds 89–90 GB on GPU 1 and keeps about 124 GB of experts in system
  RAM; about 151 GB of RAM stayed free.
- **Speed with both busy:** Qwen generated at 270 tok/s. DeepSeek generated at 107 tok/s once warm, in its usual
  one-card range.
